## <span id="jobs-toc-heading-1" data-jobs-toc="v2">🔥 <font id=前言>前言</font></span><!-- jobs-toc:heading-end -->

适用于本地收藏、只能拉取、无推送权限的 [**Git**](https://git-scm.com/) 仓库。从 [**Sourcetree**](https://www.sourcetreeapp.com/) 菜单打开独立终端，将当前分支同步到已配置的远程上游，再按每层父仓记录的提交递归检出子模块。脚本不提交、不推送、不合并本地独有历史，不创建分支。同步核验成功后，若 SourceTree 正在运行，自动打开当前仓库并执行“仓库 → 刷新”（`Cmd+R`），请求清理仓库界面缓存并重算显示；同时输出 Git 真实的待推送 / 待拉取数量。

| 检查结果 | 实际行为 |
| --- | --- |
| 本地干净且落后 | 获取远程成功后快进 |
| 本地干净且相同 | 核验提交号后结束 |
| 有暂存、未暂存、未跟踪内容 | 红字列出路径，精确输入大写 `YES` 后舍弃并同步 |
| 有本地独有提交，含领先、分叉和远程改写历史 | 红字列出提交，精确输入 `YES` 后舍弃并同步 |
| 危险 `YES` 提示处回车、`yes`、`NO`、其它输入或 `Ctrl+C` | 取消，不舍弃本地内容 |
| 当前仓库抓取失败 | 显示原始错误和退出码；空回车重新抓取，可重复直到成功，非空输入、输入结束或 `Ctrl+C` 取消 |
| 上游不明确、游离态、未完成操作，或重试期间分支 / HEAD / 上游 / 来源变化 | 停止，不清理工作区 |
| 父仓更新了子模块提交，或已有子模块仅 HEAD 漂移 | 预取并核对目标，按父仓锁定提交递归检出；不追踪子仓分支最新 |
| 子仓源码改动、未跟踪内容、已暂存 gitlink、未完成操作或无法保护的独有游离提交 | 显示具体子仓并停止；父仓 `YES` 不授权丢弃子仓内容 |
| 删除 / 改名 / 类型转换子模块、未登记嵌套仓库、忽略内容可能被覆盖 | 停止，要求单独处理 |
| 来源缺少父仓要求的子提交 | 报出仓库、来源和目标 SHA；要求发布端补齐，不退回旧分支冒充成功 |

危险确认不创建 stash 或内容备份；未提交内容与未跟踪文件被舍弃后不能依赖 Git 恢复。确认前须自行保存需要保留的内容。

## 一、<span id="usage">运行方式</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

SourceTree 仓库动作目标是本目录内的同名可执行脚本，参数为 `$REPO`。动作只负责打开 Terminal.app，不在 SourceTree 输出窗口等待输入。菜单由 [安装器](../【MacOS】安装SourceTree自定义菜单.command/README.md) 登记和更新。

终端手动运行时，在当前目录使用：

```shell
/bin/zsh \
  './【MacOS@SourceTree】⏬只拉取远程代码.command' \
  '../需要拉取的仓库'
```

不传目录时使用当前工作目录；目标内部目录会解析到所属工作树根目录。先显示内置自述并等待回车，任何非空输入取消。`--terminal-run` 供启动器传递，仍必须连接真实终端，不能用来绕过回车或 `YES`。双击脚本不会扫描其它仓库，目标不是 Git 工作树时停止。

只依赖系统 `/bin/zsh`、Git、Perl 和系统命令；SourceTree 转交终端还需要 `osascript`。检查工具真实可用性，不自动安装或升级依赖。

## 二、<span id="flow">执行流程与来源</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

1、终端回车确认后创建私有日志与单仓库动作锁。

2、拒绝 merge、rebase、cherry-pick、revert、bisect 等未完成现场及索引锁；拒绝稀疏检出、`skip-worktree` 和 `assume-unchanged`，防止隐藏改动。

3、读取当前分支的唯一 `branch.<分支>.remote` / `merge` 及远程跟踪映射。不猜测 `origin`、`main` 或默认分支，不切换分支；本地上游 `remote=.` 不适用。

4、阶段 1/2 先展示配置来源、当前 Git 配置展开后的拉取地址、仓库路径和分支，再 fetch 该远程分支。父仓 fetch 只获取该分支，不触发 Git 隐式递归，不获取标签。失败时显示原始错误、退出码、日志和重试提示；空回车重新抓取，没有重试次数上限，每次均由用户回车触发；任意非空输入、输入结束或 `Ctrl+C` 取消。每轮抓取前后核对分支、HEAD、上游、跟踪映射和来源，等待期间发现变化或未完成 Git 操作则停止。远程分支被删除时不会沿用旧缓存执行重置，须修正来源后重跑。

5、抓取成功后固定目标提交，进入阶段 2/2 检查并同步工作树。逐层读取目标树中的 `.gitmodules` 与 gitlink，预取固定子提交并检查各层源码、索引和忽略文件风险。新子模块先在临时 Git 管理目录核对目标；来源缺少任意目标时停止，不把父仓工作树推进到不完整版本。再检查当前父仓工作区及目标之外的本地独有提交；危险情况列明完整范围并要求精确输入 `YES`。抓取失败后的回车仅授权再次抓取，不能代替此处的 `YES`。

6、确认后重新核对分支、HEAD、上游、工作区与保护边界；暂存、未暂存及未跟踪内容以摘要再次核对，同一已修改文件继续编辑也会使确认失效。有变化时停止，重新运行并重新确认。

7、干净落后分支执行 `merge --ff-only --no-autostash`。有 `YES` 授权时执行 `reset --hard --no-recurse-submodules <固定目标>` 与 `clean -fd`，仅舍弃当前父仓显示过的本地内容。再逐层执行固定版本的子模块检出，相当于 `submodule update --init --checkout`，不使用 `--remote`，不回写父仓 gitlink。最后逐仓核验 HEAD 等于计划目标、工作区干净。

8、输出最终来源、目标提交与日志位置，并读取当前 HEAD 相对上游跟踪引用的实际待推送 / 待拉取数。SourceTree 运行时打开精确的当前仓库，以窗口路径标识核对目标，调用“仓库 → 刷新”（`Cmd+R`）清理界面缓存；不额外执行“刷新远程仓库状态”或 fetch，不删除磁盘缓存、账号、书签或自定义动作。自动刷新可能将目标仓库切到前台；应用未运行时跳过，不主动启动。需要当前启动终端的自动化 / 辅助功能权限，目标有对话框、前台路径不符或菜单不可用时停止刷新并提示。界面刷新失败不会重跑已经成功的 Git 同步，进程仍保留 Git 成功退出码；只有明确输出已发送刷新时才表示请求已发出，界面计数完成与否由应用重算决定。SourceTree 打开的终端显示最终退出码；手动运行以进程退出状态为准。

来源输出结构如下，示例地址仅用于说明，未部署：

```text
━━━━━━━━━━ 来源｜只拉取 ━━━━━━━━━━
对象：main → upstream/main
配置来源：https://git.example.org/team/project.git
拉取地址（本地 Git 配置展开）：https://git.example.org/team/project.git
目标位置：<当前仓库完整路径>
本次固定目标：<成功获取的完整提交号>
```

每轮先输出 `阶段 1/2｜抓取远程（第 N 次）`，成功行显示 `远程抓取成功；本次固定目标：<提交号>`，随后进入 `阶段 2/2｜检查并同步工作树`。重试沿用同一份日志，保留每次错误与尝试次数。这里只重试当前仓库的抓取；子模块预检失败、安全检查失败或同步写入开始后的失败仍停止，按日志处理后重新运行并重新确认。

URL 的配置展开不代表已验证网络重定向终点或代理出口。输出过滤地址认证信息和查询参数；日志不保存文件 diff。脚本不变更网络代理或远程配置，沿用 Git 本身的访问配置，禁用本次命令的本地 Git hooks，避免附带运行其它业务。

## 三、<span id="boundaries">清理边界与失败处理</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

- 从指定工作树向下递归已登记子模块，不向上处理更高父仓，不接管未登记独立仓库。允许普通 gitlink 更新和纯子仓 HEAD 漂移；子仓源码、暂存指针、未跟踪内容与未完成操作继续保护。子模块删除、改名或类型转换停止，保留原目录。
- 未初始化且目录为空的子模块可以新建；若工作树缺失但管理目录中已有该子模块缓存，先停止并提示恢复原工作树，保护缓存内索引和独有提交，不覆盖重建。
- 子模块按直接父仓记录的 SHA 检出，通常处于游离 HEAD，这是消费固定版本的正常状态；已有本地分支保留，不把每个子仓切到分支最新，不在消费电脑生成父仓提交。Git 的 [`--checkout` 与 `--remote`](https://git-scm.com/docs/git-submodule) 分别对应固定版本检出和追踪远端分支，两种用途不能混用。
- 保留忽略文件。`reset --hard` 可能覆盖挡路的忽略内容，因此对当前树和目标树进行路径碰撞检查，并保守按 Unicode 规范化及大小写折叠比较，兼容 Mac 常见卷；碰撞时整次清理停止，不能只依赖 `clean -fd` 不带 `-x`。
- 嵌套独立仓库、worktree 的 `.git` 文件和裸仓库单独保护，不使用 `clean -ff`。不批量处理依赖或构建目录源码，但清理候选目录中的 Git 元数据必须核对，即使目录名为 `node_modules`、`Pods`、`.dart_tool`、`build`、`DerivedData` 也不省略这项检查；非忽略的普通内容仍属于 `clean -fd` 的确认范围，发现嵌套库则在任何舍弃前停止。
- fetch 可能更新远程跟踪引用，但任何 fetch 失败都不会触发本地舍弃。取消危险确认同样不回滚已经成功获取的远程跟踪引用。
- 已开始舍弃后发生磁盘、权限或进程中断，可能留下部分完成状态，脚本不会声称事务回滚。按日志与工作区检查结果处理后再运行。
- 动作锁只能防止本脚本并行运行；执行期间避免从其它窗口编辑、切换分支或启动其它 Git 写操作。异常强杀后如锁目录仍在，确认没有运行中的任务，再手工处理日志中点名的锁。

## 四、<span id="logs">日志和常见问题</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

每次终端确认后生成独立日志，位于系统临时目录，文件名为 `【MacOS@SourceTree】⏬只拉取远程代码.年月日-时分秒.进程号.log`。运行输出给出实际完整路径，日志为纯文本并采用私有权限。正常彩色终端中的危险提示为红色；SourceTree、`NO_COLOR`、`TERM=dumb` 使用纯文本，但不放宽确认要求。

- 没有上游：先在 SourceTree 为当前已有分支配置正确的远程跟踪分支。
- Git 已同步但 SourceTree 仍显示旧数字：看日志中的 Git 实际待拉取数。脚本会向运行中的目标仓库请求 `Cmd+R` 刷新；这采用 SourceTree 的仓库缓存刷新机制，[官方版本记录](https://product-downloads.atlassian.com/software/sourcetree/ReleaseNotes/Sourcetree_4.2.19.html)中的历史说明明确手动刷新会清理缓存。若提示自动化或辅助功能权限不足，在系统设置中按实际启动终端授予对应权限，或直接在目标仓库按 `Cmd+R`。不需要重跑 Git，也不需要删除整个应用支持目录。若真实待拉取数并非零，应检查是否远程又有更新或界面查看了其它仓库 / 分支。
- `cannot lock ref ... is at ... but expected ...`：表示本地引用值与本次更新预期的旧值不同，通常需要检查 SourceTree 自动抓取或其它并发 Git 操作，不能仅凭界面显示的更新数量推断为 CDN 缓存。等并发任务结束后，在重试提示处空回车重新抓取；持续失败按原始错误排查，不自动删锁、删引用或重写配置。[Git 引用更新文档](https://git-scm.com/docs/git-update-ref)说明了旧值匹配检查。
- 游离 HEAD：先切换到明确的已有跟踪分支；脚本不猜目标、不创建分支。
- 子模块风险：按报出的具体子仓保存或处理源码、暂存指针及未完成操作后重跑，不能用父仓 `YES` 代替子仓授权。单纯父子提交不一致由脚本对齐，无需在只拉取电脑提交或推送。
- `not our ref`：目标平台缺少父仓引用的子提交。先在有权限的发布电脑补齐该平台子仓；重装、删库和在消费端提交旧指针都不能补出缺失对象。父仓、子仓及后代必须在同一下载线路上提供完整提交链。
- 已进入 merge：先在 SourceTree 检查并处理或取消现有合并，再运行本动作；脚本不会自动终止或覆盖已有合并现场。
- 终端未打开：检查系统自动化权限，或直接在 Terminal 用完整脚本路径和仓库目录运行。
- 保留本地改动：在 `YES` 提示处取消，手动复制或保存后再运行。

## 五、<span id="validation">验证范围</span> <a href="#前言" style="font-size:17px; color:green;"><b>🔼</b></a> <a href="#🔚" style="font-size:17px; color:green;"><b>🔽</b></a>

单仓版本的原有验证基线为 40 项临时真实 Git / PTY 交互测试，包括严格 `YES`、取消保留、获取失败、领先与分叉、嵌套仓库、忽略文件的大小写 / Unicode 冲突、确认期间内容变化、目录检查失败、重复运行和锁清理。

递归版本另外验证三级仓库连续多轮更新、本地领先数始终为零、深层纯 HEAD 漂移、子孙源码 / 未跟踪 / 暂存指针保护、未完成合并、新子模块、浅克隆锁定旧提交、缺少目标 SHA、忽略路径覆盖和嵌套独立仓库。来源解析另以离线矩阵覆盖多层 namespace、HTTPS / SSH、自定义端口及 Gitee HTTPS 兼容。所有业务验证使用临时远端，消费端命令记录确认没有 `commit` 或 `push`；未在实际业务仓运行同步或舍弃。

抓取重试另外以本地临时远端和真实 PTY 验证：首次成功、连续失败后多次回车成功、非空输入 / EOF / Ctrl+C 取消、非终端阻断、重试成功后仍须精确 `YES`，以及等待期间分支、HEAD、上游、来源、索引锁和跟踪映射变化时停止。抓取故障用命令替身注入，传输及快进使用真实本地 Git；不代表已复现 SourceTree 后台抓取的真实时序。

**终端配色保护：** 独立运行时，在支持完整保存与恢复配色的交互终端中临时使用黑底白字及统一强调色；正常结束、失败或可捕获中断后恢复进入前的配色，不修改终端全局偏好或 Shell 启动配置。不支持完整保护、无交互终端、`NO_COLOR`、既有纯文本模式和 Sourcetree 场景不切换配色，并沿用纯文本输出约定。强制终止（如 `kill -9`）无法由脚本自身保证恢复，请使用运行时显示的独立恢复入口。
